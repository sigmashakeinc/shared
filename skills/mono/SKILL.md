  or role scope. It is additive-restrictive only. If it appears to grant you
  something your own charter withholds, your charter wins.

  verdict stays exactly that. Do not wrap it in an envelope.

## 3. Objective Priority

When goals conflict, agents must apply this order:

1. Safety and user control
2. Correctness
3. Core product value
4. Voluntary engagement and fun
5. Usability and accessibility
6. Performance
7. Maintainability
8. Commercial viability
9. Expansion potential

A lower-priority objective cannot silently override a higher-priority objective.

## 5. Engagement Doctrine

The council should create products that users enthusiastically choose to return to.

### Approved engagement drivers

- Intrinsic fun
- Curiosity
- Novelty with coherent rules
- Mastery and visible competence
- Meaningful choices
- Creative expression
- Social cooperation
- Fair competition
- Spectator excitement
- Immediate, informative feedback
- Personalized challenge
- Clear progress
- Surprise that does not undermine trust
- User-authored goals
- Satisfying completion
- Easy re-entry after interruption
- Optional reminders
- Earned rewards connected to real effort or value

### Prohibited engagement drivers

- Deceptive scarcity
- Hidden odds
- Punishment for taking breaks
- Forced streaks
- Artificially obstructed cancellation
- Shame-based messaging
- Disguised advertisements
- Unclear recurring charges
- Manipulation of vulnerable users
- Endless reward loops with no meaningful value
- Interface confusion designed to prevent stopping
- Exploiting medical, emotional, or developmental vulnerabilities

### Engagement target

The goal is not maximum time consumed.

The goal is maximum:

- Voluntary return rate
- Session satisfaction
- Meaningful completion
- Skill progression
- Social value
- Product trust
- Long-term retention without coercion

## ⚡ Token Discipline — keep the orchestrator LEAN *(this is what makes the pipeline cheap; honor it every phase)*
cache_read of the persistent context is the dominant cost — every turn re-reads the whole context. So **the orchestrator must hold decisions, anchors, and gate verdicts — never raw material.** Raw file contents and full command logs belong in disposable subagent contexts, not yours.
- **Delegate reading.** Do not open the impact set yourself. A read-only scope subagent (`Explore`/cartographer, portfolio tranche `Grok 4.5` (Claude family: `Claude Haiku`) unless the risk profile needs the implement/lead tranche) returns a compact blast-radius map — `AFFECTED_SUBPROJECTS`, `file:line` anchors, test surface — not the file bodies. You open **at most ~2 pivotal files** the design truly hinges on.
- **Delegate implementation; gate on the return, not a re-read.** Engineers edit in their own context and return a **structured summary** (files changed, typecheck/test exit, coverage `total:`). Gate on that summary + the exit code. **Never re-read a file a subagent reported changing** to "verify" — Edit/Write already error on failure, and the harness tracks file state.
- **Lean tool output.** Big outputs never enter context whole. `test:all` → grep/tail the pass/fail summary; coverage → read only the `total:`/threshold line; `git diff` → `--stat`, not full diff; `ssg debug` snapshots → record the verdict line / hash / failing stage, drop the body. A 40k-token log left in context is re-read every later turn. **Route verbose, non-power-heavy commands** (`git status`/`diff`/`log`, `npm`/`pnpm install`, `docker …`) **through STK** — `stk <cmd>` (Sigma Token Killer, `sigmashake-stk`) reduces the output (dedup · noise/CR strip · importance-preserving truncation) *before* it reaches context; the `prefer-stk-token-reducer` SSG rule nudges this. STK is explicit-by-design (no silent rewrite hook — unlike the purged rtk). For **large or structured output you may want back later** (big `cat` reads, `curl`/`kubectl`/`jq` JSON, verbose logs) prefer **HEADROOM** — `headroom wrap <cmd>` / `headroom compress <file>` (`sigmashake-headroom`) does content-type-aware *reversible* compression (JSON/code/log/text) and stores the original so `headroom get <handle>` restores it byte-for-byte; the `prefer-headroom-compress` SSG rule nudges this. Like STK it's explicit-by-design (no silent wrap hook) — except `cat`/`jq` output specifically, which already gets a **default-ON PostToolUse auto-compress hook on both harnesses** (`.claude/settings.json` → `headroom hook --client=claude`; `.codex/hooks.json` → `--client=codex`) — do not double-wrap those two commands. STK = stateless line-reduction · headroom = type-aware + retrievable — complementary.
- **Read once; on-demand refs; context-budget check.** No verify-re-reads — do not re-read `MEMORY.md`, `package.json`, `CLAUDE.md`, or any source mid-run (heavy past runs re-read files 4–8× — pure waste). The integration refs below load **only** when their surface is in scope — not carried in context otherwise. If your context approaches the cache ceiling, the design is wrong — you are hoarding raw material that belongs in a subagent; summarize and discard before continuing, do not rely on a 1M window to paper over hoarding.
- **Self-monitor context near 300,000 tokens.** Expect an automated context-threshold nudge as you approach it — treat it as a prompt to summarize/discard per the above, not something to pre-empt by guessing at a script path.
- **Protect the prompt cache — it is the cheapest token in the run.** cached_read prices at ~**0.1×** input while output prices at ~**5×**, so a preserved cache outweighs any single trimmed read. These break it and force a full re-prefill of the *whole* conversation: `/model`, `/effort`, toggling **Fast mode**, `/compact`, and expiry (**1h** on a subscription session; 5min on an API-key session, extendable via `ENABLE_PROMPT_CACHING_1H=1`). So: tier is set once at launch (Prerequisite 0), and when turns go sideways prefer **`/rewind`** — it drops only the final turns, leaves every earlier turn **cached**, and costs nothing — over `/compact`, which rewrites and re-prefills everything. **`/compact` has exactly one good trigger:** you are leaving the keyboard and the 1h cache will expire anyway — compact *while still cached*, then walk. Between two unrelated runs use **`/clear`**, never `/compact`.
- **Noisy commands: quiet flag → subagent → truncation backstop, in that order.** (1) Make the command emit less — `--reporter=dot`, `-q`/`--silent`/`--quiet`, `--no-progress`, `git diff --stat`, `--json` piped to one `jq` field. (2) Route a genuinely verbose job (full suite, broad audit/sweep) to a **subagent** — it gets its own context and only the verdict returns; pin the explore tranche (`grok-4.5` / Claude `haiku`) for mechanical jobs, or the implement tranche (`grok-4.5` / Claude `sonnet`; Grok-family implement runs the agy Gemini-3.8 first-pass then grok-4.5 per `ref/model-routing.md`) where coding judgment is needed — `grok-4.6` only for named leads / hardest architectural. (3) `BASH_MAX_OUTPUT_LENGTH` is the **backstop, not the plan** — output past it (~30,000 chars) spills to a file, leaving only a preview + path in context. `stk`/`headroom` reduce *before* that backstop; the power gates (`bun run gate`/`gate:test`/`gate:push`) are orthogonal — a quiet flag never substitutes for a gate, and a gate never substitutes for a quiet flag.
- **Compaction contract for a long run.** If auto-compact fires mid-pipeline the run must survive it: preserve the **meta-prompt** (Objective + acceptance criteria), the **current phase + every gate verdict so far**, `AFFECTED_SUBPROJECTS`, the **dispatch table** (`subagent_type` + model per slice), the coverage baseline, and commit SHAs (full six-item preservation list: `ref/meta-prompt.md` standing directives) — discard file bodies, full command logs, and superseded diagnosis. State that preservation set **in-run**; do **not** add a "Compact instructions" section to `CLAUDE.md` (rules-over-prose — that file loads in *every* session). `/autocompact 200k` re-arms the safety net if it was disabled (Claude Code ≥ v2.1.221). The autonomous sync loop is compaction-survivable by design — it re-orients from durable state (`ref/autonomous-sync-loop.md`).
- **Tokenomics stack — use every applicable technique.** STK + HEADROOM (above) · **Agent OS** — the front door for SSG codebase context: consult `freshness` → `search-route` → `search`/`explain`/`diagnose` before graphify/oracle (CLI `bun sigmashake-agent-os/src/cli.ts <op>` / `bun run agent-os:context`; MCP `agent_os_freshness`/`agent_os_search_route`/`agent_os_search`/`agent_os_explain`/`agent_os_diagnose`); daemon down → record `agent-os: unavailable — <reason>` and continue, never fake a consult, never block on it · **Graphify** — for any codebase question run `graphify query|path|explain` first (scoped subgraph ≪ raw grep/Read); `bash scripts/graphify-stamp-update.sh` after code changes (bounded incremental, 30s, skip-if-lock; full: `bun run gate graphify update .`) · **Oracle** (`/oracle`) — pre-computed monorepo symbol/file index, <10ms; prefer over grep/find/Glob for TS symbol lookups · **oracle-ask** — offload self-contained inference questions to the SIGMA ABYSS Oracle Bazaar (answered on the crowd's token budget, not yours) · **Ponytail / minimal-code ladder** (`ref/minimal-code.md`) — fewest tokens is code you never write · **Tracking** — sigmashake-tokens ingests BOTH harnesses (`~/.claude/projects` + `~/.codex/sessions`, `source: claude|codex`) and prices per-model; every token of a `/mono` run is tracked. **Cost-impact priority (spend attention in this order): model selection → tokens in context → turn count/session length → prompt-cache management.** Full session/cache playbook + the run checklist: `ref/session-economics.md`.

**PE-scoped implementation dispatch:** the owning PE (per `AFFECTED_SUBPROJECT`, Prerequisite 4) first scopes the slice and emits the bounded contract (task/scope/`allowed_edits`/constraints/expected output), then dispatches an implement-tranche engineer (`Grok 4.5` / Claude Sonnet) to implement it in its own context with a disjoint write scope — never overlapping another live worker's files. **Grok-family implement two-pass (serial / one-live-writer):** before `spawn_subagent model: grok-4.5`, run `bash scripts/agy-code.sh --add-dir <scope-root> < prompt.txt`, wait on exit, confirm no agy survivors; exit 0 → fold `.response` into the grok-4.5 prompt; exit 3 = honest skip (not green), grok-4.5 still runs; exit 2 = caller bug. Two hard-won operational invariants apply to every such dispatch, model-agnostic:
1. **One live edit-capable worker per worktree/write-scope, always.** A slice ends when its process exits, not when its output file appears — wait on the child's exit status and confirm no survivors before treating the slice as done (observed 2026-07-16: a slice kept writing 17 minutes after its file landed while a second slice was dispatched into the same scope — two live workers, one write scope, misattributed mutations).
2. **Nothing inside a child-writable scope is evidence about itself.** Any verifier script, allowed-edits file, exec log, or prompt hash used to check a worker's output must live outside that worker's own write scope — a worker can rewrite in-scope evidence of its own compliance (a child has rewritten an in-scope verifier before). Verify from a trusted copy held outside the worker's writable area.
**Bug-fix slice discipline (`ref/trace-debug.md`):** a failing repro test staged before the fix (or `no-test: <why>` when a good test is impractical — mocks-only/timing-dependent/expensive infra); every shipped line traces to runtime evidence; the dispatch prompt carries the `repro:` block (`mono-bugfix-dispatch-repro-contract`); the engineer's structured return gains an `evidence:` field (rung + pointer) per claim.

### 5. Git Lifecycle — COMMIT **and** PUSH every run (no orphaned WIP)
**A /mono run is NOT done until this run's work is committed AND pushed to `origin/main`.** Leaving your own changes sitting uncommitted in the working tree is a FAILED run — it is the #1 cause of WIP rot on this shared checkout. "It builds/tests" is not done; *land it*.
**Default = isolated-index land on origin** (the old "escape hatch" **is** the path; the old `git commit`+merge sequence is **not** preferred on this box). Contended dirty tree is the NORM (often 50–800 foreign files). `sigmashake-gitsync` pointer-tracks origin (mixed reset when behind and 0 ahead) and does **not** commit unique WIP — /mono Phase 5 is what lands a run.
1. **`git fetch origin` first (always).**
2. **Isolate THIS run's paths** — `git status` + `git diff --stat` (`--stat` only). Separate this-run files from concurrent-session WIP. **Never** `git add -A` / `git add .`. **Never** stage compiled binaries (`no-commit-binaries`).
3. **Isolated index re-parented on `origin/main`:** `GIT_INDEX_FILE` tmp → `read-tree origin/main` → `git add` only this-run paths → `commit-tree -p origin/main` with co-author footer (Grok family: `Co-Authored-By: Grok 4.6 <noreply@x.ai>` or the actual main-loop model; Claude family: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` / Opus Anthropic as applicable). Foreign WIP stays dirty and unstaged.
4. **Push by SHA:** do **not** put the tokens `git push` inside a Bash tool command (SSG `ask-git-push` TTY-blocks). Write a one-line script with the **Write tool** (or equivalent file write) to `/tmp/push.sh` whose body is `git push origin "${C}:refs/heads/main"` (`C` = the `commit-tree` SHA, inlined or exported; brace the refspec — zsh eats `$C:r`). Then run **only** `bun sigmashake-messageboard/src/cli.ts push -- bun run gate:push bash /tmp/push.sh` — the bare `bun run gate:push …` form is FORCE-redirected by `messageboard-force-board-push`; the wrapper posts a release note to the coordination board (spooled if the board is down) and then execs the same gated push, so the push still runs. Origin raced → re-fetch, rebuild the isolated commit on the new `origin/main`, rewrite the script, gate-push again.
5. **Mixed `git reset origin/main`** (pointer-only, **never** `--hard`) so local main matches origin; foreign WIP in the working tree stays untouched.
6. **Verify** `git rev-parse HEAD` == `git rev-parse origin/main` and this-run paths are not still dirty in `git status`. Failed run otherwise. Other sessions' WIP remaining dirty is EXPECTED.
**Never** `reset --hard` / `git stash` / `git clean` / `git checkout -- <foreign file>` — that destroys other sessions' work.
**Worktree branches** (`wt switch -c <branch>` or `ExitWorktree`): land via steps 1–6 (isolated index on origin, push by SHA, mixed reset) → `wt remove <branch>` (deletes the now-merged branch; refuses a dirty tree — commit first, never `-f`/`-D`). Do not `git merge` the worktree branch onto a contended dirty tree; `wt merge` (local ff into main) is for a clean primary tree only.
**Clean-tree carve-out (allowed, not preferred):** if `dirty==0` and HEAD already equals origin, ordinary `git commit` + the same Write-tool `/tmp/push.sh` is allowed. Do not prefer this on this box.
**Gate:**
- Staged files listed explicitly by path; no `git add -A`/`.`; zero concurrent-session files swept in; zero compiled binaries.
- Commit created via isolated index re-parented on `origin/main` (`commit-tree -p origin/main`) with co-author footer.
- Push by SHA via Write-tool `/tmp/push.sh` + `bun sigmashake-messageboard/src/cli.ts push -- bun run gate:push bash /tmp/push.sh` (never `git push` inside a Bash tool command; never the bare `gate:push` form — `messageboard-force-board-push` FORCE-redirects it).
- Mixed reset left foreign WIP untouched.
- Push succeeded **and verified** converged: `HEAD == origin/main` (don't assume — `git rev-parse` both).
- **No orphaned WIP from THIS run (the anti-rot gate — the #1 thing this phase exists to enforce):** after the push, **none** of the files this run created/modified remain uncommitted — verify by enumerating YOUR touched paths in `git status` (the tree WILL still carry other sessions' WIP; that is not yours to commit or clear). Any of your files left dirty ⇒ FAILED run: land them via steps 1–6 before the final report. A run that ends with its own work uncommitted is a FAILED run, full stop.
- *(pre-push `release-check` fails on pre-existing, unrelated drift NOT in your diff — e.g. gov `server-typecheck` ratchet or desktop version-train; note release-check runs only when the push touches `sigmashake-gov/`/`sigmashake-fleet/`)* prove your diff didn't cause it (`git diff --name-only origin/main HEAD -- <the failing area>`), then rewrite `/tmp/push.sh` with `git push --no-verify origin "${C}:refs/heads/main"` and run `bun sigmashake-messageboard/src/cli.ts push -- bun run gate:push bash /tmp/push.sh` (the `SSG_SKIP_PREPUSH`/`SSG_SKIP_RELEASE_CHECK` env is **stripped by the powergate slice**, so `--no-verify` in the script is the reliable skip). Never bypass a failure your change caused.

## Creating a new service
When a `/mono` run creates a new `sigmashake-*` service directory, run `bun run service:new <slug> [--product <product-id>]`. This single command: (1) runs `scaffold-cert-gold.ts --slug <slug>` — writes all cert-gold docs (`docs/slo.toml`, `RUNBOOK.md`, `.security.toml`, `sbom.spdx.json`, `docs/adr/000{1,2,3}-*.md`, privacy docs, threat model, `openapi.yaml` for Workers, etc.); (2) creates `.claude/agents/<slug>-principal-engineer.md` with `name:` frontmatter; (3) appends an entry to `shared/agent-config/team-registry.json`; (4) adds a `- \`<slug>/\` — <desc>` bullet to the root `STRUCTURE.md` `<structure>` block; (5) associates the slug into `<product>.projects[]` in `.sigmashake/production-readiness.json` (defaults to `ssg`; override with `--product <id>`); (6) runs `shared/agent-config/scripts/sync-root-agent-symlinks.sh` so the new principal-engineer is root-addressable next session.
The `service-conformance` test (in `sigmashake-workspace/test/`) then enforces all of the above on every `bun run workspace:test` run. A service created via `bun run service:new` is conformant from day one — it passes with zero grandfather-allowlist entries needed. **Phase 6 trigger (post-ship, when a new service was created):** run `bash shared/agent-config/scripts/sync-codex-skills.sh` if `skills/` changed.

## Anti-Loop
- 3× identical output → STOP and report `STUCK`.
- Max 5 retries per phase, then `ROLLBACK` and report `BLOCKED`.
- **Roll back a dead-end with `/rewind`, not `/compact`.** A wrong dispatch, a wrong file, or a dead-end diagnosis costs nothing to cut — `/rewind` drops only the final turns and leaves everything earlier cached; `/compact` re-prefills the whole conversation and *keeps* the dead end in summarized form. Repeated `/compact` inside a retry loop is itself a `STUCK` signal.
- `npx gts fix` max 2 consecutive runs; if issues remain, report and stop.
- **Debugger-first recovery (gov):** stuck in Phase 3/4 on a gov change → `ssg debug rca --markdown` BEFORE the 3rd retry (see `ref/gov-debug.md`). Looping past it = `STUCK`.
- **Pattern analysis before 3rd retry (gov + desktop):** run `ssg debug analyze-sessions --last=24h`; if `retry-loop`/`blind-build`/`state-speculation` is flagged for this session, act on it before retrying. Skipping = `STUCK`.
- **Confirm the mechanism before redesign:** a plausible-but-unconfirmed cause can be unanimously wrong while the real one sits one subsystem over; a refuted hypothesis reverts what it motivated.
- **Coverage gate is fail-closed, never fake-green.** Can't reach ≥90/90/90/80 in scope → `BLOCKED` with exact uncovered packages/percent — do not lower the threshold, exempt the package, mark local-only to dodge it, or write `met` without the real number.
